# 设计思路与踩坑记录

本次完成两个选做题，并加入只读计分板与对局记录。必做题的五个实现文件、规则契约头文件和 84 个原测试保持完成时的版本。AI、窗口、适配器与远程视图的改动属于选做范围。

## 1. AI 直接读状态

`StateStrategy::decideCommand(const GameState &, int)` 输入状态，输出命令，没有 QObject、Player 链表或网络依赖。`AIPolicy` 只负责读取引擎状态与执行命令，单机和服务器托管复用同一路径；界面提示也调用同一策略。

候选按点数组生成：单张、对子、三张及带牌、顺子、连对、飞机及翅膀、四带二、炸弹、火箭和既有扩展。每个候选仍由 `PlayHand` 检验，并且跟牌必须通过 `canBeat()`。同点数选择最小花色，评分相同按实际牌序打破平局。没有每一步枚举全部物理手牌子集。

评分估计剩余手数，尽量保留炸弹、火箭与高牌；农民一般让队友的牌，能直接出完时例外；敌方只剩一张时优先多张领出、跟单张时考虑高牌封堵。这是确定性的启发式策略，不声称最优或必胜。只读取自己的具体牌和对手公开的 `handCount`；完整状态与隐藏信息投影必须得出相同命令。

## 2. 窗口按状态所有权拆分

| 对象 | 独占职责 | 对外边界 |
| --- | --- | --- |
| `CardTableView` | 卡牌控件、选牌、布局、动画 | 输入自己的手牌、对手余牌数和公开牌；输出选牌意图 |
| `OnlineRoomController` | RelayClient、RemoteGameSession、房间成员和连接生命周期 | 发送命令；输出权威事件、房间和聊天通知；只读视图 |
| `GameActionController` | 人类命令路由、提示、倒计时和超时行动 | 本地经适配器执行；联机发送后等待服务器确认 |
| `GameRecordModel` / `ScoreboardDialog` | 公共事件投影和显示 | 累计分、倍数、最近 300 条记录；不记录私有牌面 |
| `GamePanel` | 组装对象、菜单、主题、音效与展示回调 | 不再持有选牌数组、网络客户端、房间状态或回合计时器 |

各组件不使用 `friend GamePanel`、大上下文指针或引用主窗口私有成员。`DouDiZhuPresentation` 将窗口与展示组件作为库，让真实窗口也能参与离屏测试。

## 3. 保持唯一权威

本地命令经 `GameControlAdapter::executeCommand()` 到 `LocalSession`；网络命令强制使用连接所属座位。联机发送不提前删除手牌或推进回合，收到服务器事件后才更新视图。旧 Player 对象仍作为兼容展示缓存保留，规则与新策略不靠它们决策。

计分板消费引擎的累计分事件，不重新结算。对局记录是公共事件摘要，方便看清叫分、牌型、牌墩重置与倍数变化；它不是完整存档或可恢复回放。

## 4. 踩坑

- 只拆 `.cpp` 仍共享大类成员，无法建立职责边界；这次实际迁移了对象和状态的所有权。
- 先发 UI 信号、后同步 Player 缓存会渲染上一手牌；适配器现在先同步权威状态再通知展示。
- 超时不能通过按钮可见性猜阶段，也不能让领出者过牌；倒计时校验座位、阶段和局号，领出超时使用合法提示。
- 返回菜单需要关闭会话 AI 调度；新局再开启。旧网络对象先断信号、再延迟删除，避免断线回调伤及新房间。
- 联机不叫的 `BidAccepted(0)` 不应清零最高分；远程视图只在更高叫分时更新，并记录叫分次数。
- 动画终点也属于布局状态；窗口缩放时同步更新正在运行的位置动画终点。
- Windows 的旧 GCC 运行库会干扰新 Qt 子进程；开发工具和匹配 DLL 放在 `build`，不覆盖系统环境。离屏检查显式加载字体，不改变实际 qwindows 界面字体。

## 5. 验证与运行

```powershell
. .\build\activate.ps1
cmake -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

原七组测试保持不变。新增 `state_strategy`（独立链接 Qt Core、1000 个 seed 的对局与投影一致性）、`online_room_controller`（真实 TCP 建房、私牌隔离、重进和断线）、`optional_ui`（真实窗口组合、选牌、提示、超时、计分记录、动画缩放及菜单取消）。审阅发现的两个边界问题均以失败用例复现后修复。

游戏中点击左下方 **计分 / 记录** 查看计分板。公开房间服务端地址仍沿用原项目的配置方式。
